# Рабочее соглашение по проекту

Читай этот файл первым. Он про то, как здесь принято работать, а не про то, что делает проект — для этого есть `README.md` (обзор), `FIT-MODEL.md` (модель) и `help.html` (инструкция пользователя).

## Что за проект

Два инструмента для самостоятельного bike-fit, обе страницы на ванильном JS с инлайновым SVG:

- `index.html` — сравнение геометрий двух рам,
- `fit-lab.html` — райдер на геометрии: кокпит, посадка сидя, атакующая стойка,
- `help.html` — справка по всем параметрам.

## Жёсткие ограничения

- **Один HTML-файл на страницу.** Без сборки, без npm-зависимостей, без сервера. Страница обязана открываться двойным кликом с `file://`.
- Это правило про сам инструмент. Инструменты разработки (`regress.mjs`) — отдельные файлы рядом, в страницу не входят.
- Никаких внешних CDN и сетевых запросов из страницы, кроме уже стоящей аналитики.

## Регресс — обязателен при любой правке модели

```
node regress.mjs            сверить с эталоном
node regress.mjs --update   перезаписать эталон (только после разбора диффа)
node regress.mjs --list     выгрузить текущие значения
```

108 кейсов, 5292 значения: три реальные связки рама+кокпит из `fixtures-evo.json` на сетке sag × наклон корпуса × разведение локтей × наклон велосипеда. Допуск 1e-6.

**Порядок действий:**

1. Перед правкой прогнать регресс — убедиться, что база чистая.
2. Внести изменение.
3. Прогнать снова, **разобрать каждое расхождение** и объяснить, почему оно ожидаемо. Расхождение, которое не удаётся объяснить, — это баг, а не повод обновить эталон.
4. Только после этого `--update` и запись в `CHANGELOG.md`.

Смысл зафиксированного `regress-golden.json` именно в том, чтобы ловить регрессии **между сессиями**. Снимок, снятый с текущего кода в начале работы, ловит только то, что сломалось в этом же разговоре; ошибка, заехавшая раньше, молча войдёт в новый снимок.

## Инварианты модели

Это свойства, которые обязаны выполняться. Каждое поймало реальный баг:

- **RAD не зависит от sag.** Каретка и ручка жёстко на раме, расстояние между ними не может меняться от наклона. RAAD зависеть обязан.
- **При sag 0 и ходе, равном паспортному, таблица совпадает с паспортом** рамы до десятых.
- **Длина шатуна двигает высоту седла 1:1** в обратную сторону; толщина подошвы — 1:1 в ту же.
- **Разведение локтей не меняет ни анатомический угол локтя, ни запас по длине руки, ни положение плеча.** Оно меняет только проекционный угол, вынос локтя вбок, отведение плеча и залом запястья.
- **Никаких NaN и Infinity** ни в одном выходе на всей сетке, включая вырожденные случаи (полный разгиб руки, недостижимый руль).

## Как устроено — тонкости реализации

Не очевидно из кода, ловилось болью:

**Пресеты.** Один ключ `bikelab.presets.v1` в `localStorage`, один JSON-блоб, три вида: `geo` (рама), `ck` (кокпит + шатун, Q-factor, штырь), `body` (мерки + наклон корпуса, целевое колено, множитель RAD). Имя пресета — ключ в объекте, поэтому сохранение под существующим именем обновляет запись.

Санация в два этапа. При **импорте** ключи приводятся к числу или `null`, но белый список НЕ применяется: иначе файл из более новой версии страницы навсегда терял бы незнакомые ключи. Белый список применяется при **загрузке в состояние**, поэтому мусор туда всё равно не попадёт. Плюс `fixReq()`: обязательные поля, пришедшие как `null`, откатываются к дефолтам — частичный пресет не должен ломать солвер.

`buildInputs()` сносит разметку карточек, поэтому обработчики делегированы на `document`, а выбранное в каждой строке хранится в `psSel` и восстанавливается вызовом `psRefresh()` в конце `buildInputs()`.

Пресет рамы, сохранённый без колёсной базы, при загрузке в Fit Lab получает её вычислением из офсета: здешний солвер без базы выдаёт `NaN`.

**Передача рамы между страницами.** Кнопка «Открыть в Fit Lab» собирает хэш `#w=<радиус>&n=<имя>&f=reach~stack~hta~sta~ht~st~cs~bbDrop~wb~travelRef~travel~sag`. Если база пустая, считается из офсета той же формулой, что в `solve()`. Проверено: после переноса reach, stack и углы совпадают до второго знака.

**Аналитика.** GoatCounter, один тег на страницу, без кук. Переключатель `#toggle-goatcounter` обрабатывается своим скриптом в `<head>`, а не штатным механизмом: страницы переписывают хеш своим состоянием раньше, чем догрузится асинхронный `count.js`. События шлются хелпером `track()` из обработчиков, а не атрибутами `data-goatcounter-click` — карточки пересобираются, атрибуты пришлось бы перепривязывать. Все вызовы обёрнуты в проверку `window.goatcounter`, блокировщик ничего не ломает.

**Раскладка.** Три точки: 700 и 1160 px, ширина левой панели `clamp(330px, 25%, 500px)`. Высота схем ограничена долей высоты окна с учётом пропорций viewBox — иначе вид сбоку при пропорции почти 1:1 не помещается рядом с полями.

## Стиль кода и текста

- Комментарии в коде объясняют **почему**, а не что. Особенно там, где выбрано неочевидное допущение — такие места должны говорить, какая альтернатива отвергнута и почему.
- Интерфейс и документация — по-русски, без англицизмов там, где есть нормальное слово. Термины, у которых нет русского эквивалента (reach, stack, RAD, sag, backsweep), оставляем как есть.
- Модель описательная, а не предписывающая: показывает числа, зоны и последствия, решение принимает человек. Автооптимизатора «идеальной посадки» здесь не будет — см. §3.5 роадмапа.
- Числа в ответах пользователю подкрепляй прогоном, а не памятью. Файлы между сессиями меняются: перечитывай код, прежде чем утверждать, как он работает.

## Чего не делать

- Не обновлять `regress-golden.json` «чтобы прошло».
- Не добавлять в модель параметры, которые нельзя ни измерить, ни откалибровать по фото: коэффициент, взятый с потолка, хуже честного отсутствия.
- Не заменять прямые замеры тела антропометрическими регрессиями — направление ровно обратное точности.
- Не ломать `file://`: ни `fetch` локальных файлов, ни модулей, ни сборки.
